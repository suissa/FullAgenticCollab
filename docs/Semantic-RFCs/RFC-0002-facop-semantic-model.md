# RFC-0002 — FACoP Semantic Model

- Status: Experimental
- Category: Normative semantic

## Core model

FACoP transfers a validated reason for change, not an implementation patch.

`Contribution = Claim + ExecutableReproduction + ExpectedFailure + Provenance + Evidence`

A Contribution identifies a bounded change request. A Claim states what is believed to be wrong or missing. A Reproduction is executable evidence of the claimed failure. ExpectedFailure identifies the failure being demonstrated. Provenance records formulation context without requiring hidden chain-of-thought.

## Relations

- Contribution contains Claim.
- Claim is demonstrated by ProblemProof.
- Claim may authorize IndependentRegeneration.
- Candidate is generated by the upstream plane.
- SolutionProof evaluates the Candidate using the unchanged Reproduction.
- Evidence authorizes lifecycle transitions.

## Invariants

- A contribution MUST have one canonical identity.
- A contribution MUST NOT be equivalent to an unverified patch.
- ProblemProof and SolutionProof MUST refer to the same claim and reproduction digest.
- A candidate MUST be independently generated or explicitly identified as an upstream artifact.

## Forbidden interpretations

FACoP is not merely issue automation, test-suite-based patch submission, or a requirement to disclose private reasoning.

## Proof obligation

The complete causal chain MUST be reconstructible from immutable references and content digests.
